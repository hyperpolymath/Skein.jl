== Current focus — a standalone knot-database library (ADR-0001)

Skein.jl serves one master: general Julia users who want knot storage,
indexing, querying and equivalence checking (docs/decisions/
ADR-0001-skein-serves-one-master.adoc). *QuandleDB* — which hosts the KRL
resolution-language implementation — is the flagship in-estate *consumer*: it
wraps Skein for persistence and invariant/equivalence queries. KRL
construct/transform/resolve semantics live in QuandleDB/krl, not here; Skein's
own query surface (range/set/meta predicates, pagination, statistics) is a
plain database affordance, not a KRL operation.

* [x] Standalone `Pkg.add` / `Pkg.test()` (KnotTheory.jl weakdep-only again; AcceleratorGate dependency and accelerator extensions removed, 0.4.0)
* [x] Vestigial ABI/FFI/accelerator scaffolding jettisoned (ADR-0001)
* [ ] Alexander polynomial (standalone, via the PD / `pd_code` route)
* [ ] Query surface consolidation against Skein's own contract (INTEGRATION.adoc), with QuandleDB's needs as the first consumer input

[NOTE]
====
*Withdrawn (2026-06, restated 2026-09):* an earlier draft made the "current
focus" a realignment of Skein into a knot *graph* database — a typed
knot-relationship (edge) layer + traversal (`knot_relations` table,
connected-sum factorisation DAG, skein triples L+/L-/L0,
mutation/crossing-change; schema v5). That was authored on a mistaken
"KRL = query language" model and is withdrawn. Skein-relation resolution
belongs to QuandleDB's Resolve layer, not necessarily Skein's persistence
layer. The "maths analogue of a graph database" remains the owner's
aspirational framing; any edge/traversal or schema change must first be
re-grounded against Skein's own storage requirements.
====

== Future Horizons (v1.0+)

=== Decentralized & Federated Topology
* [ ] **Federated Skein Protocol**: Enable peer-to-peer searching of knot databases across different research institutions using a shared gossip protocol.
* [ ] **Content-Addressed Knot Storage**: Full integration with IPFS for permanent, verifiable storage of knot diagrams and their invariants.

=== Topological Machine Learning
* [ ] **GNN Embedding Index**: Native database support for storing and querying knots by their Graph Neural Network (GNN) embedding vectors, enabling "Fuzzy Topology" searches.
* [ ] **Automated Invariant Discovery**: Use the database as a training set for finding new, computationally efficient topological invariants.

=== Honest Guarantees
* [ ] **Property-test hardening**: extend the property suite to cover every invariant in PROOF-NEEDS.adoc.
* [ ] **Verified Migration Engine**: prove (or exhaustively property-test) that schema migrations preserve stored Gauss codes and invariant caches.
